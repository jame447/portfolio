Hardware Constraints & Firmware DSP Architecture

  • Strict Competition Hardware: ESP32 DevKit V1, LM393 DIP-8 Dual Voltage Comparator, single 1 MΩ RC charging resistor (measured 1.027 MΩ), 10 kΩ trimpot setting Vref ≈ 1.65 V (inside LM393 0..VCC-1.5V input common-mode window), 10 kΩ / 2 kΩ open-collector pull-up, and 0.1 µF switch hardware debounce.
  • Inverting Comparator Trick: Wiring Vc → IN1- and Vref → IN1+ forces LM393's open-collector transistor to pull OUT1 HIGH → LOW in nanoseconds, avoiding slow pull-up slew-rate sensitivity to cable stray capacitance.
  • Cycle-Accurate Critical Section: IRAM_ATTR routine under portENTER_CRITICAL(&timingMux) uses single-cycle register macros (GPIO_OUT_W1TS_REG, GPIO_IN_REG) and inline assembly rsr %0, ccount at 240 MHz for 4.17 ns/cycle resolution (~0.004 pF).
  • Pre-Rally IoT Prototyping: Initial telemetry built on NE555P (508.01 kHz baseline via hardware PCNT on GPIO 4), GPIO 34 ADC1 divider + 25 kHz PWM drying fan (GPIO 18), and Mosquitto MQTT JSON publishing (chumphon/coffee/sensor).

IoT Smart RFID Door Lock & CCTV Access Control System

Dual-MCU & Dual-SPI Hardware Engineering

  • Dual-SPI Bus Isolation: Wired concurrent MFRC522 readers on separate hardware buses — VSPI (Entry, gated by HY-SRF05 ≤ 30–45 cm) and HSPI (Exit, independent of ultrasonic proximity) so ingress and egress never collide.
  • Wake-on-Approach via ESP-NOW: Main ESP32 transmits nearby 1/0 state over peer-to-peer ESP-NOW to ESP32-CAM, sleeping camera capture when idle (5 s away hysteresis + 300 ms debounce) and waking :81/stream MJPEG live CCTV + :80/capture JPEG snapshots on entry.
  • Custom 2-Layer EasyEDA PCB & Flyback Protection: Routed custom carrier PCB (dated 2026-09-15) with JST B2B/B4B/B7B headers, 1 kΩ / 2 kΩ Echo voltage divider protecting 3.3 V GPIO from 5 V HY-SRF05 Echo, 470 µF + 100 nF rail decoupling, and 1N4007 flyback diode across the 12V / 0.6A LY-03 solenoid lock driven via relay (HIGH ≈ 5.2 s).
  • 3D-Printed Dual-Unit Wall Enclosure: Modeled main controller housing (OLED, ultrasonic, buzzer speaker holes) + separate exterior exit RFID housing + camera mount.

Security & Async Cloud Architecture

  • Zero-Wait Unlock Latency: ESP32 sends authenticated JSON (POST /access with Bearer DEVICE_TOKEN, 5 s timeout) to NestJS + MySQL + Prisma. Backend returns granted / denied immediately while fetching GET /capture :80 asynchronously in the background — ensuring slow camera frames never delay door release.
  • Full RBAC Schema: 5-table relational design (InviteCode, Admin [ADMIN | GUARD] with scrypt password hashing, User RFID UIDs, AccessLog, and retry-queued LineNotification).
  • Live Security Operations: Next.js Admin & Guard dashboards stream real-time Socket.IO events, access history thumbnails, and conditional LINE Messaging API + email alerts.
  • Engineering Post-Mortem: Documented PCB copper pour improvements, inductive transient suppression, and future roadmap (offline cache, anti-cloning 2FA, TLS & rate limiting).
